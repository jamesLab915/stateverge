StateVerge 常用 Python 指令速查（可当作操作手册）
===============================================
工作目录默认：~/StateVerge
建议每次先执行（若尚未 export）:
  cd ~/StateVerge
  export PYTHONPATH="$PWD"

示例 topic：us-separation-of-powers（将下列命令中 TOPIC 或 slug 换成你的 topic 名）

注：与路径相关的根目录为仓库根下的 **topics/<slug>/**，不是根目录的 output/<slug>/。

--------------------------------------------------------------------------------
一、项目初始化 / 检查
--------------------------------------------------------------------------------
【什么时候用】
- 第一次开项目、换电脑、出片前怀疑环境或 API
- 不清楚该用哪个子命令时，用下列入口看 --help

【做什么】
  cd ~/StateVerge
  export PYTHONPATH="$PWD"

  # 检查各集成 API / 环境（OpenAI、ElevenLabs 等，见终端输出）

  python -m src.production.ltx_batch_helper
  # Envato 下载分拣
  python -m src.utils.sort_envato

--------------------------------------------------------------------------------
二、Production 层
--------------------------------------------------------------------------------
【什么时候用】
- 新建 topic 或要补全 brief
- 改口播/主持人文案后需重新出脚本
- 要生成 LTX 分镜表、导出 LTX 侧 prompt
- 外部 LTX 已出片、要在本机拼 narrative_main
- 要加包装带、字幕、Envato 混音混剪后出 final_packaged

【做什么】
  export PYTHONPATH="$PWD"

  # 1) 生成 / 初始化 brief（若已存在会提示不覆盖）
  python -m src.production.cli --topic us-separation-of-powers --generate-brief

  # 2) 生成口播与 presenter 脚本（需 OpenAI 等与 narration 流程）
  python -m src.production.cli --topic us-separation-of-powers --generate-scripts

  # 3) 生成 LTX 场景表 ltx_scene_plan.json（依赖 brief 与 narration_script）
  python -m src.production.cli --topic us-separation-of-powers --generate-ltx-plan

  # 4) 从场景表导出 LTX 侧 prompt / manifest（不调外部 LTX API）
  python -m src.production.ltx_batch_helper --topic us-separation-of-powers --export-prompts

  # 5) 在外部 LTX/工具按 manifest 生成好各 scene 片段后，合成为 narrative_main
  python -m src.production.ltx_batch_helper --topic us-separation-of-powers --assemble

  # 6) 打包装：音乐 duck、字幕、SFX 等，输出 final_packaged.mp4（需前置产物齐）
  python -m src.production.cli --topic us-separation-of-powers --package

--------------------------------------------------------------------------------
三、Presenter 层（按顺序；同一 topic）
--------------------------------------------------------------------------------
【什么时候用】
- 要为主持人建立时间线、写 manifest
- 要生成/更新主持人配音
- 要按时间线切分对轨
- 要拼 base 与准备 Runway lip-sync 目入目出
- 手动完成 Runway 出片后，要拼段并合并进全长 narrative

【做什么】
  export PYTHONPATH="$PWD"

  # plan：规划时间线、建目录
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --plan

  # TTS：ElevenLabs 等（.env 需 ELEVENLABS_*，否则日志会提示 no-op）
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --tts

  # 按时间线切分主持人相关音频
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --split-audio

  # 为每段拼 base 视频（母版池等）
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --build-base

  # 为 Runway lip-sync 准备输入目录
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --prepare-runway

  # 在放好 Runway 输出到 lipsync_output 约定路径后，先逐段合再全长
  #（无单独名为「insert」的子命令；对应 assemble）
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --assemble-segments
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --assemble-full

  # 或：plan 起到 prepare-runway 之前的一次性备料（不含你手动的 Runway 出片 + 上面两个 assemble）
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --full-prep

     python -m src.presenter_pipeline.cli --topic us-separation-of-powers --assemble-full

     执行：which ffmpeg
  4️⃣ 若仍无法判断黑屏原因，需要看容器轨信息：
     TODO: 本仓库未附带 ffprobe 一键检查脚本，可在终端对成片手动执行：ffprobe -hide_banner <file.mp4>

9.1 「极速压缩」示例（命令均真实存在）
---------------------------------------
⚠️ 下列顺序会被很多人当作「最短路」，但**很容易在 assemble 一步失败**：

原因简述：
- `--export-prompts` 之前通常**必须先有** `brief/ltx_scene_plan.json`（需先 `--generate-ltx-plan`；见 9.2 推荐版）
- `assemble-full` 在代码中依赖 `video/narrative_main.mp4` 等；若 LTX 片段未生成就拼不出来
- 通常还需要 `build-base`、`prepare-runway`、手动的 Runway 出片、`--assemble-segments` 后，再 `assemble-full`

  cd ~/StateVerge
  export PYTHONPATH="$PWD"

  # 1. 生成内容
  python -m src.production.cli --topic us-separation-of-powers --generate-brief
  python -m src.production.cli --topic us-separation-of-powers --generate-scripts

  # 2. LTX（只导出 prompt；若上一步未先生成 ltx 计划，请先 8.2 的一行 generate-ltx-plan）
  python -m src.production.ltx_batch_helper --topic us-separation-of-powers --export-prompts

  # 3. Presenter（到 split）
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --plan
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --tts
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --split-audio

  # 4. 拼接（全长；缺前置时可能报错）
  python -m src.presenter_pipeline.cli --topic us-separation-of-powers --assemble-full

十、♻️ 重跑策略（省时间，避免全量重跑）
================================================================================
👉 当前 **没有** 全局 force 参数时，用「只重跑相关子命令」替代（见「六、常用 force」中 TODO）；
  **不要指望一条 --force-all**，应按场景挑下面子命令重跑。

1）只改口播/主持人**文案** → 通常只跑：
  python -m src.production.cli --topic <slug> --generate-scripts

2）只改**声音**（重新出 TTS）→ 通常只跑：
  python -m src.presenter_pipeline.cli --topic <slug> --tts
  python -m src.presenter_pipeline.cli --topic <slug> --split-audio
  （之后若已影响切段，自 `--build-base` 起按需继续）

3）只改/重做**主持画面与 lip 相关**（在 Runway 出片已更新时）→ 只跑 Presenter 后半段：
  python -m src.presenter_pipeline.cli --topic <slug> --assemble-segments
  python -m src.presenter_pipeline.cli --topic <slug> --assemble-full
  若仅全长合成有问题，可优先只试：
  python -m src.presenter_pipeline.cli --topic <slug> --assemble-full

4）**成片异常**（黑屏、没对上轨）在确认片源在磁盘上后，优先**局部重试合成**而不是从头：
  python -m src.presenter_pipeline.cli --topic <slug> --assemble-full
  若与包装层有关，再试：
  python -m src.production.cli --topic <slug> --package

5）**只改 LTX 出片、不改脚本** → 在新生成 ltx/generated 下片段后，只跑：
  python -m src.production.ltx_batch_helper --topic <slug> --assemble
  然后按需从 presenter 链上继续。

十一、📁 输出文件在哪里（topics/<topic>/ 下，不是根目录的 output/）
================================================================================
以 topics/<slug>/ 为根，与 `src/production/paths.py`、
`src/presenter_pipeline/fs_utils.py` 的约定一致：

  brief/               production_brief.json, ltx_scene_plan.json, packaging_manifest.json
  script/              narration_script.txt, presenter_script.json
  video/               narrative_main.mp4（LTX 拼接后在此）
  audio/               主持人相关见 presenter 子结构（如 audio/presenter/ 下片段）
  presenter/           plan/, segments/, base/, lipsync_input/, lipsync_output/, final/, manifests/
  output/              final_with_presenter.mp4, final_packaged.mp4
  ltx/                 prompts/, generated/ 等（LTX 批处理助手用）

注意：本仓库**没有**统一使用「根目录 output/<topic>/」这一结构；请以 **topics/<topic>/** 为准。若有人说「audio.wav」「sections/*.mp4」，在本项目中更接近：
- 整段或分段音频多在 topics/<slug>/audio/ 与 presenter/ 各子目录
- 分段视频多在 topics/<slug>/presenter/segments/ 、presenter/final/ 下（名称因段而异，不是固定「sections 文件夹名」的单一约定，以你磁盘为准）

十二、⚠️ 常见坑（经验总结）
================================================================================
- 没配 API key → `healthcheck` 中对应行 FAIL，进而 `--generate-scripts` 或 TTS 失败
- 没先 `--generate-ltx-plan` 就 `--export-prompts` / assemble → 缺 plan 或行为不符合预期
- LTX 片段未落盘到 ltx/generated → `--assemble` 后 narrative_main 为空或失败
- 没做 Runway 手速环节就把 output 放错路径 → `assemble-segments` / `assemble-full` 找不到片
- 没 `--split-audio` 就强行往下 → 时间线/段边界与真音频对不上
- 机器上多版本 ffmpeg、参数不统一 → 易黑屏/无声/轨错位（应用同一环境的 ffmpeg/ffprobe 排查）
- 混淆路径：成文在 **topics/<slug>/output/**，不是仓库根 **output/**

十五、一键自动出片 (auto_video)
================================================================================
  从 brief/narration_script.txt 一路跑到 topics/<topic>/output/final_mix.mp4。
  顺序：检查脚本 → selector → promote → 自动 seed video/ → 生成 timeline →
        run_pipeline --only-main → verify_final_video.sh。
  不修改 mix_engine / production / presenter_pipeline 的逻辑；任何一步失败立即终止。

  常用命令：
    python -m src.auto_video --topic watergate
    python -m src.auto_video --topic watergate --no-download
    python -m src.auto_video --topic watergate --skip-verify

  全部参数：
    --topic <slug>          (必填) 对应 topics/<slug>/
    --no-download           透传 selector：仅写 manifest，不下载素材
    --force-timeline        默认开启，给 generate_timeline 加 --force
    --no-force-timeline     关闭 --force（仅缺失时才生成 timeline.json）
    --max-video-copy 8      第 4 步从 envato/ 复制到 video/ 的上限 (默认 8)
    --skip-verify           跳过最后一步 verify_final_video.sh
    --root <path>           覆盖 STATEVERGE_ROOT / ~/StateVerge

  最终成片路径：
    topics/<topic>/output/final_mix.mp4

  日志前缀：
    [auto_video]                    总入口
    [auto_video step N/7]           第 N 步（共 7 步）
